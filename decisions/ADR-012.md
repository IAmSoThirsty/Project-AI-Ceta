# Profile activation and full-scope completion

**Document ID:** ADR-012  
**Package edition:** 1.0 / 2026-10-06  
**Document state:** DERIVED_REQUIREMENT  
**Implementation and runtime evidence:** NOT_STARTED / NOT_RUN in this delivered package.

## Status and authority

DERIVED_REQUIREMENT. This is a prewritten design decision record. It contains no fabricated owner signature, external approval or execution evidence. The implementing lead reconciles it with current adopted source at Gate A.

## Context

The system must remain coherent across cognition, authority, execution and continuity. Historical components and similarly named roles can hide different meanings and trust assumptions. This decision supplies a single explicit engineering rule for the new design.

## Decision

Qualify complete operational profiles with all applicable controls and keep unavailable mandatory capabilities open.

## Consequences

A core local workspace profile may run after its real gates; this does not mark distributed/hardware/modalities/training work complete.

## Alternatives and rationale

The alternative of silently inheriting legacy module behaviour or selecting a different rule in each component is rejected because it creates contradictory authority, evidence or lifecycle semantics. A justified replacement may be proposed with exact source, affected callers, migration and tests. Current direction is preserved until the required change authority exists.

## Verification and reopening

A profile label conceals a missing mandatory control or is presented as full completion. Bind the adopted implementation to relevant requirement groups, test IDs and actual source/configuration evidence. Only a real accepted record advances this decision to an implemented/validated state.
