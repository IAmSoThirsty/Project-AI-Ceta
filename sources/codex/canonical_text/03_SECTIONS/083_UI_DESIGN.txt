SECTION 083 — UI Design

STATUS: CONTENT-COMPLETE

PURPOSE

Define the design of interface surfaces, controls, layout, hierarchy, feedback, states, and visual affordances that let people complete authorized tasks.

REQUIRED OUTCOME

 - A scoped UI system tied to users, tasks, states, content, interaction, accessibility, devices, and outcomes.
 - Tested interface specifications with evidence, behavior, responsive rules, controls, and implementation handoff.

WHY THIS MATTERS

UI is the visible contract between people and system state. Visual clarity cannot compensate for incorrect behavior, inaccessible controls, or hidden authority.

APPLICABILITY

Applies to screens, dashboards, forms, controls, navigation, responsive surfaces, device displays, operator consoles, and system status views.

NON-APPLICABILITY CONDITIONS

No material surface, control, state, hierarchy, accessibility, content, or recovery effect; or an unchanged approved UI specification with impact recorded.

PREREQUISITES AND DEPENDENCIES

UX and interaction models, content, design system, user research, device constraints, accessibility, localization, data, identity, privacy, security, and acceptance authority.

REQUIRED INPUTS

UX and interaction models, content, design system, user research, device constraints, accessibility, localization, data, identity, privacy, security, and acceptance authority.

HUMAN RESPONSIBILITIES AND AUTHORITY

Humans approve meaning, hierarchy, inclusion, interaction authority, risk, content, and acceptance. They resolve visual or usability tradeoffs and retain correction and stop authority.

AI RESPONSIBILITIES AND BOUNDARIES

AI may generate layouts, variants, tokens, and critiques. It must preserve context, accessibility, and content meaning and must not claim comprehension or silently alter permission or hierarchy.

APPLICABLE EXISTING AGENT ROLES

UI Designer, UX Designer, Interaction Designer, Visual Designer, User Experience Reviewer, Researcher, Accessibility specialist, Architect, Tester, Verifier, Critic, Implementer, Governance Reviewer, and Documentation Writer.

REQUIRED ACTIVITIES

Define surfaces, tasks, states, hierarchy, components, content, responsive behavior, input, feedback, errors, accessibility, localization, and implementation specifications; prototype and test representative paths.

HUMAN-AI INTERACTION REQUIREMENTS

Show current state, action, actor, automation, consequence, permission, validation, and recovery. AI-generated UI remains proposed; critical controls retain accessible and non-AI alternatives.

ARCHITECTURE AND SYSTEM IMPLICATIONS

Specify component behavior, state, tokens, responsive constraints, focus, input, content, data, permission, error, telemetry, localization, and degraded rendering. Keep visual design separate from security enforcement.

OWNER COCKPIT AND USER-CONTROL REQUIREMENTS

Show UI version, surface, state coverage, device, accessibility, content, evidence, implementation status, defects, and controls to annotate, approve, correct, or restore.

REQUIRED OUTPUTS AND ARTIFACTS

UI specifications, component states, responsive and accessibility rules, prototypes, content mapping, visual assets, test results, evidence, decisions, and handoff package.

EVIDENCE REQUIREMENTS

Identify surface, device, viewport, user, state, version, method, result, and limitation. A screenshot or visual review proves only appearance in bounded conditions.

VERIFICATION AND ACCEPTANCE TESTS

Verify hierarchy, state feedback, responsive behavior, focus, keyboard and assistive access, contrast, content fit, localization, errors, permissions, loading, offline, and recovery.

FAILURE STATES AND ANTI-PATTERNS

Screenshot-driven design; color as the only status signal; clipped text; inaccessible focus; inconsistent state; decorative motion blocking task; and visual polish treated as usability evidence.

RECOVERY AND RECONSIDERATION

Disable or correct affected surface, preserve state and user intent, provide accessible fallback, and retest devices and assistive modes. Reopen when content, components, platform, population, or evidence changes.

COMPLETION CRITERIA

Surfaces, states, controls, hierarchy, accessibility, content, evidence, tests, recovery, open issues, and acceptance authority are explicit. Remain CONTENT-COMPLETE pending reconciliation, hostile review, and owner acceptance.

HANDOFF AND CONTINUITY REQUIREMENTS

Preserve UI versions, states, tokens, assets, content, findings, decisions, evidence, and next action. Hand off to Visual, Interaction, UX, Content, Design Systems, Frontend, Accessibility, and Testing.
