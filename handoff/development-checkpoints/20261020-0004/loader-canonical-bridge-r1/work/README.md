# Concrete canonical fixture to owned-caller bridge

This package is executable engineering tooling. Its concrete native path has not
been executed. A separate reviewer must examine this exact construction before
handoff. The current frozen inputs deliberately contain
`trusted_owner_ingress_reference: null`: the bridge refuses before reading a
caller-supplied grant, importing the native port, or creating any resource. No
current human approval authorizes a profile/debug/memory attempt.

`capture_bridge.py` reads bounded, duplicate-key rejecting JSON; pins its own
frozen code, the accepted R5 loader, the accepted exact V2 symbol data and NuGet
trust evidence; verifies current canonical bytes; and checks the actual live TAAR
claim, state, declared/effective write scope and exact executor. The same nonce
must bind all records. Expiry has a 150-second remaining-time reserve and a
30-minute maximum validity. The existing capture deadline remains at most
30 seconds. The bridge checks a 120-second elapsed admission limit before new
effects. These checks do not preempt a Windows API that fails to return. A final
action review must bind a separately approved outer process/custody supervisor;
this construction claims no hard timeout or native-call qualification.

The Root ingress anchor is an explicit missing dependency. After a fresh human
reply, Root must preserve the exact question and reply, record their actual
message IDs and original evidence references, bind the nonce, code hashes,
loader/V2 identities, allowed effects and destinations, and obtain review of a
successor input/freeze. This implementation never writes that anchor, edits its
inputs automatically, or issues consent. Caller-supplied strings, JSON flags,
old AC7 grants and test fixtures cannot supply the missing anchor. Root's trusted
record is an operator provenance boundary; different Python role names do not
establish Windows principal isolation or cryptographic message authentication.

The anchor binds source hashes and original message evidence rather than its own
containing freeze: pinning the containing freeze would create a circular hash.
Root reviews the successor join, then produces the exact request and static
grant. The grant must explicitly allow fresh runtime object/pipe binding within
its nonce. A derived R5-compatible approval records the original grant/message
references and says that it is a binding derivation, never a new human reply.
The request also needs the action review format already required by R5
(`decision: approve`), plus the actual accepted source and symbol review receipts
(`decision: approved`). These technical status strings come from their consumer
contracts; they are not interchangeable dictionary definitions.

The dormant `native_port.py` uses the original canonical driver's exact loader
name, `prepare_probe` and the helper's `prepare_fixture`. It rejects stale bridge,
driver/helper/reader imports before preparation and runs R5's existing pure
canonical source/default/alias validation before loading the original driver.
Original `_IsolationAPI` and `WindowsOwnedProcess` constructors remain unwrapped;
`PreparedCaller.qualification_run` is `None`. No canonical class or launcher alias
is replaced, and no code filename or qualified name is forged.

The fresh profile must be absent before creation. Only that exact new profile,
with zero capabilities and the original reserved name/SID/user, may be used and
later deleted. The original ordinary loopback connection, 30-second ordinary
hold target, five protected sentinels, child pipe closure, worker arguments and
isolation oracle are preserved. The bridge calls the real
`owned_caller.execute_prepared_capture`; it never replaces the worker with a
mocked production service. It reads the actual nonce-bound `ATTEMPT.json`, raw
`stdout.bin`/`stderr.bin`, `RESULT.json` and `RETIREMENT.json`, verifies their hashes
and child identity, and uses persisted parent token/exit/custody evidence. It
does not poll the capture owner's closed handles.

Known ordinary resources have one cleanup attempt. An interrupted allocation,
unknown close, missing retirement, pending debug event, constructor uncertainty
or residual native resource keeps the profile and exact unresolved custody
record. Unknown native calls, owner cleanup and child pipe closure are not
replayed. No profile is adopted, recursively removed or replaced. A source or
oracle failure remains a failure even when useful diagnostic bytes were captured;
the command exits nonzero. A successful diagnostic is still not native/profile
qualification, installed-product acceptance or proof of the original timeout's
cause.
