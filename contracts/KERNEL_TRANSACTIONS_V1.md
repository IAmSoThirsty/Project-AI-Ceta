# Kernel transactions, development version 1

Status: IMPLEMENTED_NOT_QUALIFIED. This is the CMP-02 command owner over the
existing CMP-03 v2 store. It preserves the twenty admitted records, the public
store ports, original sources and the default closed execution boundary.

## Source obligations and limits

SPEC-19, ARCH-03, original master 212-230/838-850 and TR-07/08 require exact
preparation binding, atomic reservation/intent and durable one-use consumption.
ADR-019 requires complete owner-selected dependencies. OperationPermit and
StandingGrant retain their original distinct states and field definitions.
Original B009/B057-B064 remain NOT_RUN: the tests here use synthetic owners
within one process and do not exercise authentic consent, protected broker
processes, external mutation or independent readback.

TR-06, TR-09 and TR-11 still have unresolved intermediate-state meanings.
This implementation starts from an explicitly owner-bound prepared fixture
basis. A PROPOSED or VALIDATED caller label does not establish preparation.
It implements no preceding legal preparation transition and does not adopt a
new interpretation of the original transition catalog. The owner question
about required intermediate states remains unresolved until actually answered.

## Composition and operations

`compose_kernel` captures one store providing AtomicStorePort and HistoryPort,
one codec, one installation scope and an explicitly supplied owner set.
Application use cases delegate prepare/consume/revoke and evidence resolution
to this same kernel. Missing owners cause KERNEL_OWNERS_UNAVAILABLE before
reads or writes. No production identity, clock, approval or protected-resource
provider is supplied. Python callbacks and well-formed types do not establish
authentication. `require_runtime_admission` unconditionally denies, including
when fixture owners are supplied. No method dispatches an external effect.

Preparation resolves a persisted basis by proposal identity. Its original
proposal bytes and computed commitment, principal/session, task revision,
adapter/version, registry, full owner input, candidate, review/approval,
policy/environment and complete resource read set are bound. The captured
owner must independently verify that preceding decision and evidence. Human
approval evidence may be absent only when the proposal does not require it;
policy may impose additional obligations through the owner. No reference is
manufactured to satisfy a missing approval.

One final store snapshot includes all selected dependencies, current budget,
and new permit/reservation/intent/issuance keys. Its complete expectations are
rechecked inside the existing transaction. A changed discovery basis denies.
The fixed installation projections are kernel-control and kernel-registry;
registry entries identify adapter/version/commitment/operation. A project task
and every owner-selected resource have distinct revision projections. Grant
purpose, grantee, operation and exact resource access constrain the proposal.
The grant may reside in the same project or installation scope. Other project
grants require an unimplemented bridge and deny. More than 128 distinct cells
deny explicitly; dependencies are never truncated. The 4096-resource leaf
bound is preserved and does not imply this transaction profile admits it.

Preparation commits PREPARED permit, HELD reservation, INTENT_COMMITTED
effect metadata, budget and issuance association together. A proposal cannot
be prepared again through its durable issuance projection. Event IDs, permit
IDs, reservation IDs and nonce are generated by the command owner. The full
operation input commitment includes the original proposal, complete prepared
basis, current grant commitment, exact deadline and dependency expectations,
and actual reservation/issuance references. Tombstoned issuance indices cannot
be treated as never issued; only generation zero admits first preparation.

Consumption reloads the exact issued permit and bounded-replays its issuance
event through the durable sequence/prior-head association. It verifies every
selected dependency, current grant, reservation, peer/session and deadline.
It commits CONSUMED permit, CHARGED reservation, ADMISSION_REDEEMED effect
metadata, budget and consumption sequence/prior-head association together.
Duplicate or restarted consumption cannot revive the permit. Evidence lookup
replays that actual committed consumption event and checks exact payload,
event ID and prior head. These event facts do not prove an external effect.

The trusted internal `resolve_consumption(ParsedRecord)` callback is preserved,
including historical SETTLED selectors. Public ingress instead passes the exact
wire and opaque context to `resolve_consumption_for_peer`. That query binds the
stored intent's principal/session, proposal ID/scope, read-set scope and exact
grant key to the permit. It verifies the consumed payload's causal reference and
the actual event's actor/session/causation. The same generation-bearing permit
and intent cells and the same live context are checked again before disclosure.
It performs no current-grant/deadline admission, write, refund, renewal or replay.
The result describes a coherent historical read cut; no ongoing resource lease
or general audit-reader authority is established. Public consumed recovery uses
the same evidence checks while retaining its original selector API.

Revocation commits REVOKED grant and incremented bounded revocation generation
against the same grant cell used by preparation/consumption. Revocation first
invalidates a competing consumption. Consumption first remains spent after
revocation. This database ordering does not qualify original B062 or resolve
the interval between consumption and an irreversible external effect. The
actual broker's current fencing, identity and protected-handle checks remain
mandatory unfinished work. Revocation performs no sweep or automatic refund.

## Explicit engineering allocation profile

`ceta-allocation-liability-v1` is an engineering profile for finite reservation
liability, not source-prescribed usage measurement or billing. All seven
schema dimensions are treated as additive allocation units in this profile,
including wall_time_ms. They do not represent observed elapsed time, tokens,
I/O bytes or settled effects. The original sources do not resolve that policy.

For each dimension: recovery + held + charged <= limit, with exact nonnegative
safe integers. Available = limit - recovery - held - charged. Preparation
moves the proposal ceiling to held; consumption moves the whole ceiling from
held to charged. It does not settle actual usage. Recovery floors are supplied
by the owner, not claimed as source-defined quantities. No automatic release,
refund, renewal, retry or replay restores authority. Limit must match the
current grant budget. This one-operation profile requires positive wall time
and max_effects = 1; unsupported shapes deny explicitly.

The security deadline is bounded by both grant expiry and that wall-time
ceiling using trusted-owner samples, with exact nanoseconds. Restart, resume,
time-epoch change, rollback, uncertainty and expiry deny consumption. Grant
budget and consumed state remain durable. Real clock custody is unqualified.

The compatible optional store commit guard runs captured current-context,
preparation/admission-owner and deadline checks after writes/fault hooks and
immediately before COMMIT; a rejection rolls
back the entire batch. It is an owner-composed internal callback, not a request
field or a storage-selected policy. Owner checks must be bounded, repeatable,
side-effect-free and nonreentrant into kernel/store commands. They use identical
original proposal, PREPARED permit, revocable grant and basis inputs. They verify
current trusted facts without requiring transaction-owned rows to keep their
pre-transition values after COMMIT. They must not consume consent, allocate
authority, perform effects or wait for a model, user or external work. Deadline
checks follow owner checks, and context is reauthenticated again at completion.
The deadline is checked again after that final authentication, which can consume
time independently of the permit's shorter security lifetime. Both PREPARED and
CONSUMED public recovery bind proposal, read-set and supported grant scopes.
Revocation rechecks its exact context and owner predicate without adding a
grant-expiry or trusted-time-progress requirement. The kernel rechecks
after COMMIT before returning. A post-commit stale result denies but preserves
the durable reservation or consumed permit; it must be resolved from history,
never refunded or blindly retried. This does not atomically pin a physical
clock during SQLite COMMIT or qualify the external irreversible boundary.
Default identity-only broker admission remains closed. The selected native CPU
owner implements retained admission under OS6 in NATIVE_OWNER_SESSION_V1.md;
its exact current checks and protected-resource custody remain required through
the irreversible access interval. That implementation supplies no native
qualification or general runtime activation.

Budget, reservation, intent and projection values are internal versioned
metadata, not additional admitted record types. Working event names are
kernel.intent.committed, kernel.permit.consumed, kernel.grant.revoked and
kernel.development.allocation; the originals do not register these spellings.
An installation-owned budget change receives a same-scope admitted
PolicyDecision payload binding the complete change bundle. Its ALLOW means
this development reducer accepted the allocation change; it is not an
authenticated policy verdict or permission for effects. Cryptographic
authentication, full operation semantics, settlement/refund policy, hierarchy
of accounts and runtime qualification remain open.

## Proposal recovery and internal intent-v2

The additive `recover_preparation(ActionProposal wire, original context)` query
returns the matching stored PREPARED or CONSUMED OperationPermit when the caller
never received its generated permit ID. It never calls preparation, a positive
owner predicate, the clock or store commit. The original authenticated request
and principal/session remain bound throughout the lookup. A new logical session
has no automatic right to recover another session's issuance.

New preparations explicitly write `ceta-kernel-intent-v2` internal metadata with
the original grant commitment. Exact legacy v1 shapes remain supported by
consumption, permit recovery and evidence lookup. They are never rewritten by a
query. The proposal route denies legacy intent-v1 with
`KERNEL_RECOVERY_INPUT_EVIDENCE_UNAVAILABLE`; an original permit selector remains
usable through its existing recovery API. Original twenty admitted schemas do
not change, and this versioned metadata is not another positive authority owner.

The query checks the durable issuance association, original proposal bytes and
commitment, stored subject, actual PREPARED issuance payload, event identity,
predecessor, actor/session, causal proposal and immutable current permit fields.
It recomputes the original operation input commitment using the historical grant
commitment, exact basis, proposal, deadline, dependencies and issuance/reservation
references. This binds fields absent from the permit, including adapter_version
and budget. Cost and represented basis/deadline fields are checked separately.
Current consumption must resolve its actual durable event through the existing
validator. Generation-bearing issuance/permit/intent cells are checked again at
the final cut; a changed or ABA-restored association denies.

Current grant/resource/time predicates are not sampled as new admission. An
expired or revoked preparation can remain a historical PREPARED observation
without becoming usable authority. A CURRENT_RECORD has no effect, settlement,
renewal or transaction claim. The response wrapper binds only represented
proposal fields; full historical input validation belongs to this kernel query.
Bounded selected cells and one returned replay row do not bound total history
validation or native I/O occupancy. Existing trusted-time, resource, consent,
installed, isolation and independent qualification obligations remain open.
