## Component and subsystem tests

| Component | Integrated behavior | Invariant |
| --- | --- | --- |
| [24.01](24.01-BUILD-ORCHESTRATION/README.md) | Pin source and dependencies; validate configuration; build in a controlled environment; record outputs; reproduce or explain declared nondeterministic fields; hand off exact artifacts. | The build must identify the actual local source tree used, including relevant uncommitted files. |
| [24.02](24.02-VERSION-MANAGEMENT/README.md) | Assign a product release identity; validate component and schema compatibility; generate an immutable release manifest; bind version labels to exact artifacts and evidence. | A version label is a human identifier and never substitutes for content digests. |
| [24.03](24.03-PACKAGING/README.md) | Assemble only approved artifacts; validate contents and permissions; create a native installer or portable package; test clean installation and offline use; preserve user data on upgrade and removal. | Packaging cannot add unreviewed executable content after qualification. |
| [24.04](24.04-RELEASE-INTEGRITY/README.md) | Bind release artifacts to the manifest; sign through approved protected facilities where configured; verify trust and exact bytes; record provenance and distribution identity. | An unsigned artifact is labeled accurately and cannot be presented as trusted-signed without evidence. |
| [24.05](24.05-UPDATE-AND-ROLLBACK/README.md) | Validate the exact update; preflight compatibility and capacity; create a recovery point; apply staged changes; verify startup and data; roll back or forward-repair under declared rules. | Rollback preserves known revocations, deletion decisions, and user data created after the recovery point where required. |
| [24.06](24.06-PRODUCT-COMPLETION/README.md) | Reconcile full approved scope; verify every mandatory gate; exercise complete installed workflows; inspect evidence independently; issue an accurate product-completion decision. | No approved requirement is removed merely to make the completion report pass. |


Run these flows through actual local implementations after unit tests. Bind results to exact source, dependencies, configuration, environment, and artifact bytes. A mock-only test cannot qualify a native enforcement or installed-product claim. Preserve failed, blocked, skipped, and not-executed cases separately. Use [the cross-system scenarios](../ACCEPTANCE-CRITERIA/END-TO-END-SCENARIOS/README.md) for user-workflow qualification.
