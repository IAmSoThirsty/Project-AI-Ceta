## Component and subsystem tests

| Component | Integrated behavior | Invariant |
| --- | --- | --- |
| [13.01](13.01-PROJECT-MANAGEMENT/README.md) | Open an owner-selected project; validate path boundaries; register the local baseline; restore authorized interface state; expose project structure and health. | Switching projects also switches context, resource scope, and pending-decision visibility. |
| [13.02](13.02-SOURCE-EDITOR/README.md) | Load exact source bytes; preserve encoding and line conventions; track edits; request governed save; reconcile external changes; display current diagnostics. | Unsaved editor buffers and filesystem content are distinct versions. |
| [13.03](13.03-CHANGE-INSPECTION/README.md) | Compute exact changes; present text and binary summaries; stage selected modifications; obtain scoped approval; preserve revision history and recovery links. | Approval binds to the displayed diff and target identities, not a mutable staging label. |
| [13.04](13.04-TERMINAL-WORKSPACE/README.md) | Create a scoped terminal session; authorize commands; stream bounded output; preserve process ownership; stop or close cleanly; retain safe history. | An interactive terminal cannot become an ungoverned route around command execution policy. |
| [13.05](13.05-VERSION-CONTROL/README.md) | Use available local revision facilities or native snapshots; isolate work; compare revisions; reconcile conflicts; publish verified changes while preserving owner state. | Revision operations require the same file and history authority as other effects. |
| [13.06](13.06-DEVELOPMENT-PREVIEW/README.md) | Launch a controlled local preview; bind it to a source revision; observe rendered behavior; capture test evidence; recover preview and workspace state separately. | A preview is a test environment and cannot establish release qualification by appearance alone. |


Run these flows through actual local implementations after unit tests. Bind results to exact source, dependencies, configuration, environment, and artifact bytes. A mock-only test cannot qualify a native enforcement or installed-product claim. Preserve failed, blocked, skipped, and not-executed cases separately.
