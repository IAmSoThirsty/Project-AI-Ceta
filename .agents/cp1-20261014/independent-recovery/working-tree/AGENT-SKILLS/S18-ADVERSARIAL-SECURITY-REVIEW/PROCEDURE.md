# S18 procedure

## Goal

Reproducible boundary findings with impact, exact evidence, and verified repairs.

## Domain-specific sequence

1. Trace untrusted inputs to privileged effects. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
2. Test injection, traversal, replay, stale identity, secret leakage, and extension escape. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
3. Inspect native enforcement. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
4. Reproduce fixes independently. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
5. Preserve evidence. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.

## Integration and evidence

Apply the mapped local application's existing language, architecture, and qualified facilities. Keep one canonical owner for authority, state, evidence, and resource admission. Record expected versus observed outcomes at each consequential boundary. Use independent oracles rather than merely reproducing the implementation's assumptions. Preserve failed checks and unresolved effects for the receiver.

## Stop conditions

Stop the affected operation when authority expires, scope changes, source preconditions fail, required enforcement is unavailable, or evidence indicates an uncertain external effect. Inspect and reconcile before retrying. Do not erase data or weaken controls to make progress appear successful.

## Completion check

Each claimed boundary holds under the specified adversarial fixtures or has an explicit blocking finding.

Before handoff, construct and evaluate the adverse fixture: A review tests production targets without scope approval or substitutes model confidence for observed enforcement. The final report must identify the actual test state rather than implying a test ran because this procedure describes it.
