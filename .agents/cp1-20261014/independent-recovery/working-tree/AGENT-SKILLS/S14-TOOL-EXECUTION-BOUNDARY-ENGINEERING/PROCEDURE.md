# S14 procedure

## Goal

A governed adapter with exact-input binding, qualified restrictions, stop behavior, and receipts.

## Domain-specific sequence

1. Normalize arguments. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
2. Classify transitive effects. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
3. Bind target identity. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
4. Validate current authority. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
5. Install restrictions. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
6. Dispatch once per operation identity. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
7. Observe real effects. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
8. Reconcile partial and unknown outcomes. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.

## Integration and evidence

Apply the mapped local application's existing language, architecture, and qualified facilities. Keep one canonical owner for authority, state, evidence, and resource admission. Record expected versus observed outcomes at each consequential boundary. Use independent oracles rather than merely reproducing the implementation's assumptions. Preserve failed checks and unresolved effects for the receiver.

## Stop conditions

Stop the affected operation when authority expires, scope changes, source preconditions fail, required enforcement is unavailable, or evidence indicates an uncertain external effect. Inspect and reconcile before retrying. Do not erase data or weaken controls to make progress appear successful.

## Completion check

Denied requests never reach the adapter and observed effects stay within approved scope.

Before handoff, construct and evaluate the adverse fixture: A retry, terminal, maintenance, or IPC path bypasses the gate. The final report must identify the actual test state rather than implying a test ran because this procedure describes it.
