# S22 - Documentation And Traceability

## Input and output

Require: Accepted implementation behavior, requirements, test results, source and artifact identities, and existing documentation.

Produce: Current file, contract, operation, migration, and release guidance with validated links.

## Procedure

Read [prerequisites](PREREQUISITES.md) and [the input contract](INPUTS.md) before acting. Follow [the complete procedure](PROCEDURE.md) for the assigned local task.

1. Trace requirements to files and tests.
2. Describe actual behavior.
3. Identify exact evidence.
4. Preserve local integration decisions.
5. Validate references and examples.
6. Label proposed and observed work separately.

## Verification

A reader can navigate requirement to implementation to test to evidence without invented references.

Use [the verification rules](VERIFICATION.md) and preserve actual source, environment, execution, and artifact evidence. Treat this specific failure as a required adverse fixture: A completion report claims work solely because it appears in a plan.

## Failure and handoff

Follow [failure handling](FAILURE-HANDLING.md) when prerequisites, authority, or evidence are insufficient. Transfer results using [the handoff requirements](HANDOFF.md) and [the output contract](OUTPUTS.md). Never substitute a completion narrative for observable evidence.

These are native construction instructions. They do not grant host permissions, activate runtime skills, or authorize effects by themselves. The assigned task and existing CETA authority remain controlling.
