# S23 procedure

## Goal

An installed-runtime qualification record and accurate release decision for the exact candidate.

## Domain-specific sequence

1. Validate manifests. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
2. Install on clean targets. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
3. Run complete local workflows. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
4. Test interruption, update, and rollback. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
5. Verify data preservation and source-to-binary binding. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
6. Block unmet critical gates. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.

## Integration and evidence

Apply the mapped local application's existing language, architecture, and qualified facilities. Keep one canonical owner for authority, state, evidence, and resource admission. Record expected versus observed outcomes at each consequential boundary. Use independent oracles rather than merely reproducing the implementation's assumptions. Preserve failed checks and unresolved effects for the receiver.

## Stop conditions

Stop the affected operation when authority expires, scope changes, source preconditions fail, required enforcement is unavailable, or evidence indicates an uncertain external effect. Inspect and reconcile before retrying. Do not erase data or weaken controls to make progress appear successful.

## Completion check

The distributed bytes are the same bytes exercised by current installed-product tests.

Before handoff, construct and evaluate the adverse fixture: A development-tree test run qualifies a different packaged build. The final report must identify the actual test state rather than implying a test ran because this procedure describes it.
