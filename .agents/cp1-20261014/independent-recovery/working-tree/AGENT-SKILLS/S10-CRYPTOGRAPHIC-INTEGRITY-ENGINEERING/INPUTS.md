# S10 input contract

## Required domain input

Approved trust model, established local cryptographic facilities, canonicalization rules, and key lifecycle policy.

## Common fields

Include task and requirement IDs, assigned logical units, mapped local paths, exact source revisions, canonical contracts, approved effect and data scope, resource limits, expected output shape, acceptance IDs, reviewer identity, and any unresolved decisions. References must resolve to actual authorized sources. Separate exact user statements from interpretations and observed implementation facts from proposed design.

## Validation

Check identity, version, digest, access, completeness, and compatibility before work begins. Preserve original source bytes and attribution. A changed input that alters effects or acceptance requires a revised task decision. Missing or contradictory input is not filled by guesswork; record the uncertainty and perform only the independently valid portion of the task.
