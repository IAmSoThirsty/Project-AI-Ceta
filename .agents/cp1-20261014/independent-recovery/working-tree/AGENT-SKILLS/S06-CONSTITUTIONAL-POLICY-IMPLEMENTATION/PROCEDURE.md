# S06 procedure

## Goal

Version-bound policy evaluation with exact source traceability and controlled activation.

## Domain-specific sequence

1. Preserve rule text. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
2. Parse and type-check. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
3. Implement declared precedence. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
4. Return explicit unresolved conflicts. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
5. Bind decisions to proposal and policy digests. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
6. Test amendments and revocation-sensitive caches. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.

## Integration and evidence

Apply the mapped local application's existing language, architecture, and qualified facilities. Keep one canonical owner for authority, state, evidence, and resource admission. Record expected versus observed outcomes at each consequential boundary. Use independent oracles rather than merely reproducing the implementation's assumptions. Preserve failed checks and unresolved effects for the receiver.

## Stop conditions

Stop the affected operation when authority expires, scope changes, source preconditions fail, required enforcement is unavailable, or evidence indicates an uncertain external effect. Inspect and reconcile before retrying. Do not erase data or weaken controls to make progress appear successful.

## Completion check

Missing facts and unresolved conflicts never yield implicit permission.

Before handoff, construct and evaluate the adverse fixture: The implementer invents a constitutional exception to make a test pass. The final report must identify the actual test state rather than implying a test ran because this procedure describes it.
