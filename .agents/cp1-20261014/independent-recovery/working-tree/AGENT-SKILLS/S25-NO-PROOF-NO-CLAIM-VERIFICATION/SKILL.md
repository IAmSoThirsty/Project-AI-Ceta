# S25 - No Proof No Claim Verification

## Input and output

Require: A proposed completion statement, artifact references, execution records, tests, and known evidence gaps.

Produce: A claim ledger classifying each statement as supported, contradicted, incomplete, or not-executed.

## Procedure

Read [prerequisites](PREREQUISITES.md) and [the input contract](INPUTS.md) before acting. Follow [the complete procedure](PROCEDURE.md) for the assigned local task.

1. Split compound claims.
2. Identify required observations.
3. Inspect exact evidence.
4. Check freshness and scope.
5. Separate design, implementation, execution, and qualification.
6. Rewrite unsupported statements accurately.

## Verification

Every delivered factual completion claim has an inspectable supporting observation.

Use [the verification rules](VERIFICATION.md) and preserve actual source, environment, execution, and artifact evidence. Treat this specific failure as a required adverse fixture: A plausible summary, generated file count, or confidence score substitutes for actual verification.

## Failure and handoff

Follow [failure handling](FAILURE-HANDLING.md) when prerequisites, authority, or evidence are insufficient. Transfer results using [the handoff requirements](HANDOFF.md) and [the output contract](OUTPUTS.md). Never substitute a completion narrative for observable evidence.

These are native construction instructions. They do not grant host permissions, activate runtime skills, or authorize effects by themselves. The assigned task and existing CETA authority remain controlling.
