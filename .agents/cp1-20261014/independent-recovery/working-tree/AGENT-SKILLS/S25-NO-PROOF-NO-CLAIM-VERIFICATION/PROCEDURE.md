# S25 procedure

## Goal

A claim ledger classifying each statement as supported, contradicted, incomplete, or not-executed.

## Domain-specific sequence

1. Split compound claims. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
2. Identify required observations. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
3. Inspect exact evidence. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
4. Check freshness and scope. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
5. Separate design, implementation, execution, and qualification. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
6. Rewrite unsupported statements accurately. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.

## Integration and evidence

Apply the mapped local application's existing language, architecture, and qualified facilities. Keep one canonical owner for authority, state, evidence, and resource admission. Record expected versus observed outcomes at each consequential boundary. Use independent oracles rather than merely reproducing the implementation's assumptions. Preserve failed checks and unresolved effects for the receiver.

## Stop conditions

Stop the affected operation when authority expires, scope changes, source preconditions fail, required enforcement is unavailable, or evidence indicates an uncertain external effect. Inspect and reconcile before retrying. Do not erase data or weaken controls to make progress appear successful.

## Completion check

Every delivered factual completion claim has an inspectable supporting observation.

Before handoff, construct and evaluate the adverse fixture: A plausible summary, generated file count, or confidence score substitutes for actual verification. The final report must identify the actual test state rather than implying a test ran because this procedure describes it.
