# S11 - Memory And Retrieval Engineering

## Input and output

Require: Memory and source contracts, access scope, provenance rules, and retrieval or deletion fixtures.

Produce: Attributed canonical memory, rebuildable indexes, conflict-aware retrieval, and validated context inputs.

## Procedure

Read [prerequisites](PREREQUISITES.md) and [the input contract](INPUTS.md) before acting. Follow [the complete procedure](PROCEDURE.md) for the assigned local task.

1. Preserve originals.
2. Label inference and explicit statements.
3. Index committed versions.
4. Filter access before exposure.
5. Retain contradictions.
6. Propagate corrections and deletions through caches and summaries.

## Verification

Retrieved records retain correct sources and revoked or deleted content cannot reappear through derived indexes.

Use [the verification rules](VERIFICATION.md) and preserve actual source, environment, execution, and artifact evidence. Treat this specific failure as a required adverse fixture: A summary erases an explicit correction or turns speculation into a user statement.

## Failure and handoff

Follow [failure handling](FAILURE-HANDLING.md) when prerequisites, authority, or evidence are insufficient. Transfer results using [the handoff requirements](HANDOFF.md) and [the output contract](OUTPUTS.md). Never substitute a completion narrative for observable evidence.

These are native construction instructions. They do not grant host permissions, activate runtime skills, or authorize effects by themselves. The assigned task and existing CETA authority remain controlling.
