# Construction skill registry

Stable skill IDs and their observable completion oracles. Skill presence does not prove the corresponding engineering task has been executed.

| Skill | Positive oracle | Adverse fixture |
| --- | --- | --- |
| [S01 Local Baseline Inspection](S01-LOCAL-BASELINE-INSPECTION/SKILL.md) | Every proposed real source path exists in the inspected baseline or has an explicit approved create decision. | A remote or remembered layout conflicts with the actual local files. |
| [S02 Requirements Decomposition](S02-REQUIREMENTS-DECOMPOSITION/SKILL.md) | No approved requirement is orphaned, silently narrowed, or replaced by a vague completion label. | A difficult requirement is dropped to make the plan appear complete. |
| [S03 Contract First Design](S03-CONTRACT-FIRST-DESIGN/SKILL.md) | Producer and consumer conformance fixtures exercise identical semantics, including denial and uncertainty. | A consumer privately widens a security-critical field or assumes unknown states mean success. |
| [S04 File Specification Implementation](S04-FILE-SPECIFICATION-IMPLEMENTATION/SKILL.md) | The resulting file satisfies its positive, negative, recovery, and contract obligations without unrelated edits. | A stub or superficial wrapper is presented as end-to-end implementation. |
| [S05 Architectural Dependency Analysis](S05-ARCHITECTURAL-DEPENDENCY-ANALYSIS/SKILL.md) | The construction graph is acyclic and every affected contract consumer is accounted for. | A runtime message loop is incorrectly treated as a mandatory build-order cycle. |
| [S06 Constitutional Policy Implementation](S06-CONSTITUTIONAL-POLICY-IMPLEMENTATION/SKILL.md) | Missing facts and unresolved conflicts never yield implicit permission. | The implementer invents a constitutional exception to make a test pass. |
| [S07 Authority Boundary Implementation](S07-AUTHORITY-BOUNDARY-IMPLEMENTATION/SKILL.md) | A stale or revoked capability cannot authorize effects through any supported entry path. | A signature-valid token bypasses current revocation or target changes. |
| [S08 State Transition Engineering](S08-STATE-TRANSITION-ENGINEERING/SKILL.md) | Conflicting updates cannot both commit and terminal states cannot be bypassed. | A restarted worker overwrites a newer stop or revocation state. |
| [S09 Durable Storage Engineering](S09-DURABLE-STORAGE-ENGINEERING/SKILL.md) | Each injected crash yields a documented prior, committed, or explicitly uncertain state without silent data loss. | An in-memory success acknowledgement precedes durable commit. |
| [S10 Cryptographic Integrity Engineering](S10-CRYPTOGRAPHIC-INTEGRITY-ENGINEERING/SKILL.md) | A modified payload or wrong-domain signature fails while valid historical evidence remains inspectable. | A home-grown primitive or unsigned local file is described as absolute tamper-proof authority. |
| [S11 Memory And Retrieval Engineering](S11-MEMORY-AND-RETRIEVAL-ENGINEERING/SKILL.md) | Retrieved records retain correct sources and revoked or deleted content cannot reappear through derived indexes. | A summary erases an explicit correction or turns speculation into a user statement. |
| [S12 Agent Workflow Engineering](S12-AGENT-WORKFLOW-ENGINEERING/SKILL.md) | Duplicate deliveries and stale workers cannot produce conflicting canonical effects. | A producer agent self-certifies its deliverable as independently verified. |
| [S13 Model Inference Qualification](S13-MODEL-INFERENCE-QUALIFICATION/SKILL.md) | The selected model completes the declared task classes within measured limits and stops safely. | Advertised capability or artifact size is treated as measured runtime qualification. |
| [S14 Tool Execution Boundary Engineering](S14-TOOL-EXECUTION-BOUNDARY-ENGINEERING/SKILL.md) | Denied requests never reach the adapter and observed effects stay within approved scope. | A retry, terminal, maintenance, or IPC path bypasses the gate. |
| [S15 Desktop Interface Implementation](S15-DESKTOP-INTERFACE-IMPLEMENTATION/SKILL.md) | Critical approval, denial, stop, and recovery workflows function through accessible controls. | A control looks safe while an alternate keyboard or IPC path still performs an unauthorized effect. |
| [S16 Test Generation And Execution](S16-TEST-GENERATION-AND-EXECUTION/SKILL.md) | A test fails on the known defect and observes the required corrected behavior. | Generated tests merely restate the implementation or are reported passed without execution. |
| [S17 Failure Injection And Recovery](S17-FAILURE-INJECTION-AND-RECOVERY/SKILL.md) | Every fault point yields the documented durable state and preserves already committed effects. | A timeout is assumed to prove no external action occurred. |
| [S18 Adversarial Security Review](S18-ADVERSARIAL-SECURITY-REVIEW/SKILL.md) | Each claimed boundary holds under the specified adversarial fixtures or has an explicit blocking finding. | A review tests production targets without scope approval or substitutes model confidence for observed enforcement. |
| [S19 Evidence Chain Validation](S19-EVIDENCE-CHAIN-VALIDATION/SKILL.md) | Every accepted claim is tied to current admissible evidence and every gap remains visible. | A valid signature is mistaken for proof of successful behavior or factual truth. |
| [S20 Performance And Resource Analysis](S20-PERFORMANCE-AND-RESOURCE-ANALYSIS/SKILL.md) | The system stays within its declared envelope and stop remains responsive under load. | Averages hide severe stalls or estimates are labeled as observed measurements. |
| [S21 Cross Subsystem Integration](S21-CROSS-SUBSYSTEM-INTEGRATION/SKILL.md) | The full workflow uses one canonical authority, state, and evidence path without bypasses. | A second hidden implementation creates conflicting sources of truth. |
| [S22 Documentation And Traceability](S22-DOCUMENTATION-AND-TRACEABILITY/SKILL.md) | A reader can navigate requirement to implementation to test to evidence without invented references. | A completion report claims work solely because it appears in a plan. |
| [S23 Release Qualification](S23-RELEASE-QUALIFICATION/SKILL.md) | The distributed bytes are the same bytes exercised by current installed-product tests. | A development-tree test run qualifies a different packaged build. |
| [S24 Independent Reproduction](S24-INDEPENDENT-REPRODUCTION/SKILL.md) | A distinct verifier reproduces the required outcome from the supplied artifacts and evidence. | The verifier approves by trusting the producer narrative or their own earlier implementation. |
| [S25 No Proof No Claim Verification](S25-NO-PROOF-NO-CLAIM-VERIFICATION/SKILL.md) | Every delivered factual completion claim has an inspectable supporting observation. | A plausible summary, generated file count, or confidence score substitutes for actual verification. |
