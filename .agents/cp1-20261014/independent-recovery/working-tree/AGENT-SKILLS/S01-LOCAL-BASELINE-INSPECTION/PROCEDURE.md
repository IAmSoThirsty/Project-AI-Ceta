# S01 procedure

## Goal

A source-hashed inventory, entry-point map, current test catalog, and observed integration decisions.

## Domain-specific sequence

1. Resolve the selected root and link boundaries. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
2. Inspect language and build metadata. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
3. Enumerate canonical data and authority owners. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
4. Inspect tests and release paths. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.
5. Classify reuse, extend, and create decisions from evidence. For this step, preserve the exact input references, decision rationale, and output evidence required by the assigned unit.

## Integration and evidence

Apply the mapped local application's existing language, architecture, and qualified facilities. Keep one canonical owner for authority, state, evidence, and resource admission. Record expected versus observed outcomes at each consequential boundary. Use independent oracles rather than merely reproducing the implementation's assumptions. Preserve failed checks and unresolved effects for the receiver.

## Stop conditions

Stop the affected operation when authority expires, scope changes, source preconditions fail, required enforcement is unavailable, or evidence indicates an uncertain external effect. Inspect and reconcile before retrying. Do not erase data or weaken controls to make progress appear successful.

## Completion check

Every proposed real source path exists in the inspected baseline or has an explicit approved create decision.

Before handoff, construct and evaluate the adverse fixture: A remote or remembered layout conflicts with the actual local files. The final report must identify the actual test state rather than implying a test ran because this procedure describes it.
