## Component and subsystem tests

| Component | Integrated behavior | Invariant |
| --- | --- | --- |
| [11.01](11.01-EXECUTION-GATE/README.md) | Validate immutable operation inputs; verify current authority; reserve resources and evidence capacity; atomically record admission; dispatch through qualified isolation. | A missing, stale, revoked, or mismatched prerequisite prevents dispatch. |
| [11.02](11.02-EXECUTION-SANDBOX/README.md) | Construct a least-authority worker environment; verify actual restrictions; launch the bound worker; observe effects; terminate and verify cleanup. | An isolation mechanism is usable only for the effects its target-platform qualification covers. |
| [11.03](11.03-EFFECT-CONTROL/README.md) | Declare intended effects; bind target and preconditions; observe actual operations independently; compare expected and actual effects; contain deviations. | A process return value is not sufficient proof of its filesystem or network effects. |
| [11.04](11.04-STOP-AND-CANCELLATION/README.md) | Accept an authenticated stop; prevent new admissions; signal workers; escalate termination by policy; observe residual effects; persist the final cancellation outcome. | Stop acknowledgement, worker termination, and effect completion are separate facts. |
| [11.05](11.05-EXECUTION-TRANSACTIONS/README.md) | Persist intent; stage reversible local changes; perform authorized effects; commit observations; reconcile interrupted transactions; compensate only with explicit scope. | Local database atomicity cannot make unrelated external effects atomic. |
| [11.06](11.06-OCTOREFLEX-BOUNDARY/README.md) | Reconcile the existing native enforcement boundary; translate approved restrictions; qualify enforcement and observation on the target platform; attest actual installed policy. | Platform-specific enforcement claims require target-platform evidence; a missing backend is never described as active. |


Run these flows through actual local implementations after unit tests. Bind results to exact source, dependencies, configuration, environment, and artifact bytes. A mock-only test cannot qualify a native enforcement or installed-product claim. Preserve failed, blocked, skipped, and not-executed cases separately.
