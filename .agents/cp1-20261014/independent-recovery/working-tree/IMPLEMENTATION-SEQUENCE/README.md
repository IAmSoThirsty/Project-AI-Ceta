# Implementation sequence

The phases organize work by outcome; the validated prerequisite graph controls actual file admission. A subsystem can contribute an early contract or minimal shell and receive full feature integration later. No phase bypasses required authority, evidence, or qualification.

| Phase | Goal | Exit |
| --- | --- | --- |
| [Phase 00-LOCAL-CETA-DISCOVERY](PHASE-00-LOCAL-CETA-DISCOVERY.md) | Inspect the actual owner-selected local application without modifying it. | A source-hashed baseline and existing acceptance inventory exist; no remote layout is assumed. |
| [Phase 01-ARCHITECTURE-RECONCILIATION](PHASE-01-ARCHITECTURE-RECONCILIATION.md) | Map every logical unit and preserve canonical ownership. | Every logical unit has an evidence-backed mapping decision or an explicit blocking owner decision. |
| [Phase 02-CORE-CONTRACTS-AND-STATE](PHASE-02-CORE-CONTRACTS-AND-STATE.md) | Establish canonical declarations, fixtures, durable state, protected trust, and minimum evidence. | Foundation interfaces and crash-consistency checks are usable without opening general worker effects. |
| [Phase 03-AUTHORITY-AND-ENFORCEMENT](PHASE-03-AUTHORITY-AND-ENFORCEMENT.md) | Qualify identity, constitutional decisions, capability admission, and native effect boundaries. | Denied, stale, revoked, and malformed operations cannot reach effectful adapters through any supported entry path. |
| [Phase 04-INTELLIGENCE-FOUNDATIONS](PHASE-04-INTELLIGENCE-FOUNDATIONS.md) | Qualify local models, memory, context, and source handling. | Local intelligence works within measured resource limits and cannot promote retrieved content into authority. |
| [Phase 05-AGENTS-AND-WORKFLOWS](PHASE-05-AGENTS-AND-WORKFLOWS.md) | Construct durable task graphs, native skills, bounded agents, and companion task coordination. | Multi-step work resumes safely, preserves uncertainty, and produces evidence-backed outcomes. |
| [Phase 06-ENGINEERING-AND-OPERATIONS](PHASE-06-ENGINEERING-AND-OPERATIONS.md) | Integrate complete local engineering, workspace, scheduling, communication, and research flows. | Representative owner workflows traverse real native interfaces and preserve local data and authority. |
| [Phase 07-USER-EXPERIENCE-AND-EXTENSIONS](PHASE-07-USER-EXPERIENCE-AND-EXTENSIONS.md) | Complete the owner-facing application and optional extension lifecycle. | All required controls are usable and authoritative; optional integrations remain optional to local operation. |
| [Phase 08-FULL-SYSTEM-QUALIFICATION](PHASE-08-FULL-SYSTEM-QUALIFICATION.md) | Execute all mandatory unit, component, subsystem, and cross-system gates. | Every mandatory obligation has current admissible evidence; unmet checks remain release-blocking. |
| [Phase 09-PRODUCT-DELIVERY](PHASE-09-PRODUCT-DELIVERY.md) | Build and deliver the exact qualified installed product. | The delivered artifact is the exact install-tested candidate and the release decision is evidence-backed. |
