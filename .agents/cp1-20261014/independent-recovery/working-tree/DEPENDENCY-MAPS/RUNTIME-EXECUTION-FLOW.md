# Runtime execution flow

## Human request to verified outcome

Human interaction enters through an authenticated native command or attributed conversation turn. Companion Intelligence preserves exact intent, identifies consequential ambiguity, and assembles authorized context. Planning produces a bounded task contract with explicit outputs and effects. Orchestration assigns qualified agents and skills with scoped ownership and resources. Tools normalize exact arguments and declare all transitive effects.

The constitutional service evaluates the exact proposal under the approved rule revision. The identity and authority service binds authenticated principal, session, delegation, and approval into a scoped capability. The execution gate rechecks current authority, policy, revocation, target identity, resources, and evidence capacity. The qualified native boundary runs the approved worker and observes actual effects. The result is recorded with artifacts, state transitions, and evidence. Independent verification evaluates acceptance against the exact delivered revision. The interface reports what was proposed, executed, observed, and verified separately.

## Stop path

The owner's authenticated stop reaches the native control path independently of model generation and ordinary task queues. New admissions close first. Stop propagates to task descendants and owned processes. The system observes acknowledgements, actual termination, committed effects, and uncertainty separately. It records a recoverable result and leaves unresolved external outcomes for reconciliation.

## Recovery path

Startup inspects durable intent, state, worker identity, target versions, and receipts. It preserves user data and known security decisions. Safe reads and confirmed idempotent operations may resume within current authority. Unknown effects require inspection before retry. Compensation is a separate approved action. The interface restores drafts and views without repeating previous actions.

## Evidence path

Exact inputs, approved effects, authority decisions, dispatch observations, output artifacts, stop events, recovery, and verification are linked by stable operation identities and content digests. Protected internal journal operations follow the bootstrap service-authority model and do not create recursive logging requirements. Missing observation or invalid integrity blocks the corresponding verification claim.
