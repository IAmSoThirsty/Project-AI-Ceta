## Component and subsystem tests

| Component | Integrated behavior | Invariant |
| --- | --- | --- |
| [18.01](18.01-CRYPTOGRAPHIC-IDENTITY/README.md) | Create or import authorized protected keys; bind intended uses and devices; sign or verify through handles; rotate with historical trust records; revoke compromised material. | Private keys are never copied into ordinary logs, model context, or portable memory exports. |
| [18.02](18.02-SECRET-PROTECTION/README.md) | Store secrets under authenticated encryption through qualified facilities; issue short-lived scoped access; prevent context and log leakage; rotate and invalidate old references. | Secret access is purpose-bound and auditable; plaintext lifetime is minimized without promising impossible universal memory erasure. |
| [18.03](18.03-SECURITY-POLICY/README.md) | Define protected boundaries and controls; evaluate requests against the active policy; install qualified enforcement; verify actual activation before admitting effects. | A policy document is not evidence that an operating-system restriction is active. |
| [18.04](18.04-RISK-AND-ANOMALY/README.md) | Collect authorized telemetry; compare against scoped baselines and explicit rules; classify anomalies; request or trigger only preauthorized responses; retain explainable evidence. | Anomaly detection can support restriction or escalation but cannot establish guilt, truth, or new authority. |
| [18.05](18.05-INCIDENT-RESPONSE/README.md) | Open an incident; preserve relevant evidence; apply authorized containment; assess scope; repair and requalify; reopen effects only after verified recovery. | Containment must preserve evidence and avoid unrelated destructive cleanup. |
| [18.06](18.06-SECURITY-ASSURANCE/README.md) | Inspect dependency and trust integrity; run boundary-focused checks; assemble evidence; classify open findings; gate release according to explicit acceptance rules. | Integrity, vulnerability status, and runtime confinement are assessed separately. |

A mock-only test cannot qualify a native enforcement or installed-product claim. Preserve failed, blocked, skipped, and not-executed cases separately.
