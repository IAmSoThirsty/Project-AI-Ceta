## Component and subsystem tests

| Component | Integrated behavior | Invariant |
| --- | --- | --- |
| [21.01](21.01-EXTENSION-MANIFESTS/README.md) | Define extension content and interfaces; validate manifest and dependencies; inspect required effects; stage qualification before activation. | An extension must declare startup, update, background, and uninstall effects as well as normal tool effects. |
| [21.02](21.02-EXTENSION-LIFECYCLE/README.md) | Stage verified artifacts; qualify in isolation; request activation; switch revisions atomically; revoke or uninstall with data and authority cleanup. | An update is a new revision requiring compatibility and effect review. |
| [21.03](21.03-INTEROPERABILITY-CONTRACTS/README.md) | Negotiate compatible schemas; authenticate the peer; translate only declared semantics; enforce scope and message limits; reject incompatible or ambiguous operations. | Protocol translation cannot widen permissions or reinterpret a denied action as success. |
| [21.04](21.04-EXTENSION-SECURITY/README.md) | Assign an extension principal; grant minimum capabilities; launch in qualified isolation; verify code integrity; monitor and revoke on boundary failure. | Extension identity and authority are distinct from the owner and host process. |
| [21.05](21.05-NATIVE-EXTENSION-KIT/README.md) | Provide native extension construction guidance and contract fixtures; generate only owner-requested templates in the future implementation; qualify extensions against the same runtime rules. | Extension development conveniences cannot weaken production admission or verification. |
| [21.06](21.06-EXTENSION-CATALOG/README.md) | Index inspectable extension metadata; verify integrity and review state; filter compatibility; present approval requirements; keep acquisition and activation separate. | Catalog visibility is not an endorsement, installation, or grant of authority. |


Run these flows through actual local implementations after unit tests. Bind results to exact source, dependencies, configuration, environment, and artifact bytes. A mock-only test cannot qualify a native enforcement or installed-product claim. Preserve failed, blocked, skipped, and not-executed cases separately.
