## Component and subsystem tests

| Component | Integrated behavior | Invariant |
| --- | --- | --- |
| [20.01](20.01-HARDWARE-DISCOVERY/README.md) | Inspect actual available hardware and runtime limits; measure usable capacity; monitor changes; publish a versioned capability profile with uncertainty. | Total physical capacity, currently free capacity, and safely reservable capacity are different values. |
| [20.02](20.02-RESOURCE-BUDGETING/README.md) | Define per-task and shared budgets; reserve atomically; meter actual use; throttle or stop at limits; release reservations after verified cleanup. | Budget changes that expand approved effects or data destinations require a new authority decision. |
| [20.03](20.03-WORKLOAD-ADMISSION/README.md) | Estimate requirements; validate budgets and environment; reserve capacity; queue or admit fairly; fence expired reservations; release only after cleanup. | Checking capacity without reserving it does not constitute admission. |
| [20.04](20.04-RESOURCE-PRESSURE/README.md) | Detect sustained pressure; prioritize control and evidence; throttle optional work; stop unsafe admissions; recover gradually after measured stability. | Degradation reduces optional capability without weakening governance or evidence requirements. |
| [20.05](20.05-OPERATIONAL-DIAGNOSTICS/README.md) | Collect scoped resource telemetry; identify bottlenecks; compare against qualification envelopes; run offline and failure probes; report measured limits. | Operational reports distinguish measured behavior from inferred causes. |
| [20.06](20.06-INFERENCE-ACCOUNTING/README.md) | Meter observed inference usage; distinguish estimates and provider reports; charge parent and child tasks once; enforce budgets; reconcile interrupted streams. | Usage estimates, reported counts, and measured local counts remain labeled and are not silently interchangeable. |
