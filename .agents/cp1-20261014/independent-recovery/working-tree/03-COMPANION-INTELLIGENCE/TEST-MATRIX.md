## Component and subsystem tests

| Component | Integrated behavior | Invariant |
| --- | --- | --- |
| [03.01](03.01-COMPANION-IDENTITY/README.md) | Create a persistent companion profile; bind it to approved identity and preferences; evolve it through recorded changes; expose only currently available capabilities. | Changing a profile cannot change owner authority or governing policy. |
| [03.02](03.02-DIALOGUE-INTELLIGENCE/README.md) | Accept a turn; preserve exact user wording; identify consequential ambiguity; assemble authorized context; generate a response plan; expose factual basis and proposed actions. | A conversational acknowledgement does not constitute approval for unspecified effects. |
| [03.03](03.03-CONTINUITY-AND-ADAPTATION/README.md) | Load continuity records; apply explicit preferences; propose uncertain adaptations; reconcile interrupted sessions; restore task and dialogue references. | Context compression or profile adaptation must preserve explicit corrections and authority boundaries. |
| [03.04](03.04-INITIATIVE-AND-DELIBERATION/README.md) | Identify a useful initiative; state rationale and alternatives; assess authority; ask for decisions where required; create a governed task only after valid approval. | Initiative may propose action; it cannot self-approve authority-bearing consequences. |
| [03.05](03.05-COMPANION-OPERATIONS/README.md) | Translate approved plans into tasks; request tools through orchestration; observe progress; present results and interruptions with evidence links. | The companion reports tool results but never forges them or bypasses the execution gate. |
