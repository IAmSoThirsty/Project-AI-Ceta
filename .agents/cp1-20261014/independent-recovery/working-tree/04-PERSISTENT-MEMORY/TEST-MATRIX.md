## Component and subsystem tests

| Component | Integrated behavior | Invariant |
| --- | --- | --- |
| [04.01](04.01-MEMORY-RECORDS/README.md) | Validate provenance and consent; classify a record; write its durable content and version; publish indexing work after commit; preserve correction lineage. | An inference is labeled as an inference and never silently becomes a user statement. |
| [04.02](04.02-MEMORY-INDEXING/README.md) | Build indexes from committed records; apply access scope before candidate exposure; rank authorized candidates; attach source and version information; rebuild when stale. | Index entries cannot reveal records the caller is not authorized to retrieve. |
| [04.03](04.03-MEMORY-CONSOLIDATION/README.md) | Select eligible memory versions; group related content; preserve conflicts and exact evidence; propose consolidated records; retain reversible lineage. | Consolidation cannot discard explicit corrections, consent restrictions, or contrary evidence. |
| [04.04](04.04-MEMORY-PROVENANCE/README.md) | Bind memory claims to exact sources; verify references and access; record transformations; expose version history and invalidation signals. | A valid content digest proves content identity, not the truth of the remembered claim. |
| [04.05](04.05-MEMORY-LIFECYCLE/README.md) | Evaluate retention and access; honor authorized correction or deletion; invalidate indexes and caches; record minimal tombstones; reconcile backups and exports. | Deletion promises must specify active stores, indexes, cached summaries, exports, and backup retention separately. |
| [04.06](04.06-MEMORY-PORTABILITY/README.md) | Export authorized records with manifests; validate imports in staging; reconcile identities and conflicts; commit accepted records; verify reconstructability. | Importing memory never imports execution credentials or governing authority. |
