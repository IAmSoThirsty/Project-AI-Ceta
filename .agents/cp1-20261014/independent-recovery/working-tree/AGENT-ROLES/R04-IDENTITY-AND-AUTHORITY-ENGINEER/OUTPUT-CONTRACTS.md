# R04 output contract

## Domain deliverable

Authority flows with verified ancestry, exact proposal binding, and tested revocation races.

## Required handoff fields

| Field | Required content |
| --- | --- |
| Task and unit identities | Exact requirement, subsystem, component, file, and acceptance IDs covered. |
| Source changes | Mapped local paths, before and after digests, change rationale, and preserved unrelated owner changes. |
| Contract bindings | Canonical schema revisions, producer and consumer paths, compatibility and migration decisions. |
| Artifacts | Actual output references and digests; never only claimed filenames. |
| Verification | Executed procedures, fixtures, environment, raw logs, observed results, and explicit failed or unexecuted checks. |
| Recovery | Known committed effects, uncertain operations, rollback or compensation limits, and preserved user data. |
| Review | Named reviewer, independent reproduction results, findings, and acceptance decision. |


## Status semantics

Use proposed, implemented, tested, integrated, independently verified, and release-qualified only when the corresponding evidence exists. A partial deliverable remains partial. Do not collapse blocked, failed, skipped, and not-executed obligations into a success percentage.
