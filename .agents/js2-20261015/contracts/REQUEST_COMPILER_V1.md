# CETA request compiler working contract — version 1

This is the working contract for CMP-07/WP-06 in the authorized rebuild_ios
development namespace. Candidate implementation and integration must be checked
against this contract and the complete original requirements. It is not evidence
of installed, model, native, security or formal-gate qualification.

## Ownership and intake

The compiler preserves the exact immutable original and latest saved task bytes.
Interpretation remains separate and inspectable. It never promotes an attributed
meaning proposal into accepted intent, consent, a grant or an effect permit.

The application captures the compiler at composition. A request may choose a
supported interaction profile and bounded output request; it cannot select its
trusted source, state, runtime, rendering, tokenization, authority, reservation
or clock owner.

Public task intake obtains a fresh task.load result through the existing owned
native service. It joins the exact captured command/attempt/response and validates
the native task result. Compiler results must match the complete immutable
loaded TaskInput, captured task identifier and native CAS revision. Revalidation
must return the exact retained PreparedRequest. It retains both the draft-cell CAS revision and the
separate objective revision. Unsaved local edits remain separate. A changed task
basis or newer local edits require review rather than silent compilation of the
previous basis. Native opaque request contexts expire at their own receive
boundary and must not survive asynchronous compilation.

## Source and meaning discipline

One compiler serves the supported conversation, investigation, coding,
monitoring, maintenance, planning, review, probe and modality lanes. A profile is
not another inference provider or a permission grant.

Owner-selected context separates binding instructions, quotations, untrusted
data, history, model proposals and verified records. Role labels or imperative
source text are not effect security boundaries. Binding status comes from
current admitted owner policy, never from a document's claim or a request field.

Conversation receives relevant conversation context without coding-only output
rules or internal audit identifiers. Project instructions must remain scoped.
Original requests, negations, exclusions, rejected meanings, uncertainty,
corrections and supersession remain inspectable. Derived meaning is proposed,
and an inspectable primary objective is required. Derived fields must retain
their source participation when conversation or token policies omit sources;
mandatory source conflicts deny rather than silently weaken the interpretation.
Semantic fidelity requires separate source-grounded evaluation; structure
and a model self-rating cannot establish understanding.

Only ambiguity that changes the task or authority warrants a bounded material
clarification. Intentional openness and nonmaterial questions do not become
mandatory loops. Exact quotation retrieval returns the selected actual bytes
and source/version or an unresolved outcome. It never fabricates a plausible
prior quotation or treats a correction as proof of an earlier error.

## Exact assembly and outcomes

The constructor-captured backend renders the actual pinned template and
tokenizes that exact payload, including the backend's special-token behavior.
Template, tokenizer, model configuration and runtime identity are bound across
the operation. Unsupported or absent owners remain typed denials; guessed
counts cannot establish exact token accounting.

Mandatory input and output reservation are checked against the selected context
capacity. Mandatory content never silently drops. Optional omissions remain
explicit and attributed; task-changing omissions require review. Overflow keeps
the draft, original input and conflict inspectable.

Compilation returns one immutable PREVIEW, CLARIFICATION, OVERFLOW or DENIED
outcome. A PREVIEW is a candidate cognitive preparation. It issues no effect
permit and does not bypass the existing unavailable positive authority owners.

## Prepared bindings and revalidation

ContextEnvelope v1 remains its existing closed record schema. A versioned
internal prepared-request wrapper must bind the missing runtime identity,
source/version table, authority and fence generations, reservation witness and
deadline/clock epoch, together with actual payload and token identities.
Internal metadata is not a twenty-first admitted record type.

Preparation uses the complete owner-selected relevant dependency set. Before
future admission/dispatch, revalidation obtains fresh authenticated state and
checks task/objective, source revisions, policy, authority/fence, reservation,
runtime/model/template/tokenizer and deadline/cancellation. Unrelated journal
activity alone does not invalidate the request.

An expired or replaced preparation requires rebuilding; revalidation does not
renew it. In this version, human waiting continues to consume the captured
preparation deadline; there is no non-security task-budget pause. Waiting cannot
extend security validity. Compiler-authored reservation/time strings cannot qualify a transactional
reservation or trusted security clock.

Compilation and preview share cancellation and deadline custody with dispatch.
Application compilation runs outside the Qt callback and active store
transaction. Stop cancels its work immediately and retains ownership until the
worker's termination is observed. A late outcome cannot replace newer drafts,
change the selected task or qualify a stopped request. Cancelled superseded
previews may lose compiler registry custody while their immutable results remain
readable. Retirement cannot make an old preview current or grant authority.

Application worker construction and launch are separate outcomes. A constructor
failure before any start invocation cancels and retires the reserved absent
worker, preserves the prior immutable result/draft/native observation, and uses
CONTEXT_WORKER_CONSTRUCTION_FAILED. An interrupted start is LAUNCH_UNCERTAIN;
neither a missing thread identifier nor is_alive=False proves that no native
thread was created. Its cancellation and ownership remain retained until the
target's completion and actual thread exit are observed. Stop reports STOPPING
while that launch is unresolved. Generic Thread.start cannot supply an actual
no-launch receipt; production native ownership/launch reconciliation remains
required, and an unresolved launch is not claimed repaired by a status change.

ShutdownCoordinator captures the same service and session. Its exceptional-exit
path requests compiler cancellation before native termination and polls both
owned lifetimes. Native service STOPPED alone cannot retire a compiler worker.
An expired cleanup wait reports unresolved ownership and preserves the original
application failure; it does not invent stopped work or reconciled effects.

## Verification and remaining obligations

Meaningful tests cover exact byte preservation, quotation/source roles,
conversation isolation, material and nonmaterial ambiguity, mandatory overflow,
optional omissions, exact rendered token bindings, stale source/model/policy/
authority/reservation/task state, expiry, shared cancellation, late results and
worker completion. The native intake additionally needs actual disposable
create/save/load and denial/interruption evidence.

Controlled fixtures establish their tested paths only. Production interpretation,
pinned model/runtime/template/tokenizer operation, trusted clock/reservation and
protected-resource owners, UI composition, durable recovery and original case
qualification remain explicit until implemented and verified.

Full WP-06 includes all four REQ-09 groups, all five REQ-11 groups and original
B022/B025–B032/B064. This contract does not remove standing grants, obligations,
security budgets, expiry or the remaining product qualification lanes.
